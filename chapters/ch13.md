# 第13章：规模法则——大就是好吗？（2020–2021）

2020年5月，OpenAI发布了GPT-3。1750亿参数，训练数据约5000亿token，训练成本估计超过1000万美元。这是当时最大的语言模型，参数量是GPT-2的100倍。

GPT-3的发布不只是"又一个大模型"——它提出了一个根本性的问题：**模型能力是不是主要取决于规模？如果继续增大，会不会涌现出全新的能力？**

这个问题的答案深刻地影响了整个AI行业的方向。

---

## GPT-3：1750亿参数的巨兽

### In-context Learning：不给梯度，只给例子

GPT-3最令人惊讶的发现不是它在基准测试上的得分，而是它的**In-context Learning**能力。

之前的范式是"预训练+微调"——修改模型参数来适应新任务。GPT-3展示了一种全新的范式：**不修改任何参数，只在输入中给几个例子，模型就能学会新任务**。

```
输入：
"Translate English to French:
cheese => fromage
cat => chat
dog =>"

GPT-3输出："chien"
```

模型没有针对翻译任务做任何微调——它只是看到了几个例子，就理解了"翻译英语到法语"这个任务并执行。

这种能力在小模型（GPT-2）上几乎不存在。它只在模型大到一定程度后才出现——这就是**涌现能力**（Emergent Abilities）。

### 涌现能力：小模型做不到，大模型突然会了

涌现能力是GPT-3之后最引人深思的现象。某些任务的能力不是随模型规模线性增长的——在某个规模以下几乎为零，过了某个阈值后突然上升。

```
模型规模 → 能力
小模型（<10B）：基本没有In-context Learning能力
中等模型（10B-100B）：简单任务的In-context Learning
大模型（>100B）：复杂任务的In-context Learning、思维链推理、代码生成
```

涌现能力的本质至今仍有争议。一种观点认为这是真正的质变——大模型的表示能力确实发生了飞跃。另一种观点认为这是统计上的连续增长被评估方式扭曲了——如果用更精细的指标，"涌现"可能只是平滑增长曲线上的一个点。

不管本质如何，涌现能力的存在有一个重要的实践含义：**继续增大模型规模可能有质的回报**，而不只是量的积累。这为整个行业的"scaling up"战略提供了合理性。

---

## Scaling Laws：性能与规模的幂律关系

2020年1月，OpenAI的Jared Kaplan等人发表了《Scaling Laws for Neural Language Models》，用大量实验数据揭示了语言模型性能与三个规模维度之间的关系。

### 三个维度

1. **参数量N**：模型的可学习参数数量
2. **数据量D**：训练token数量
3. **算力C**：训练消耗的总浮点运算数

### 核心发现

Loss与每个维度各自呈**幂律关系**：

```
L(N) ∝ N^(-αN)    αN ≈ 0.076
L(D) ∝ D^(-αD)    αD ≈ 0.095
L(C) ∝ C^(-αC)    αC ≈ 0.050
```

这意味着：
- 参数量增加10倍 → Loss降低约15%
- 数据量增加10倍 → Loss降低约18%
- 算力增加10倍 → Loss降低约12%

幂律关系的重要性在于：**它是可预测的**。你可以在小规模上测量幂律指数，然后预测大规模模型的性能。这让投资决策变得有据可依——花1000万美元训练一个模型之前，你可以先花1万美元验证预测。

### 最优算力分配

Scaling Laws还给出了一个关键结论：**给定固定算力预算，应该按什么比例分配参数量和数据量？**

答案：当算力增加时，参数量和数据量应该**同步增长**，参数量略快于数据量。具体来说，最优比例约为：

```
N ∝ C^0.73
D ∝ C^0.27
```

这意味着：如果你的算力增加10倍，参数量应该增加约5.4倍，数据量增加约1.9倍。不是只增大模型——数据也要增长，只是增长得慢一些。

### 后果

Scaling Laws深刻地影响了整个AI行业：

1. **投资逻辑变了**：从"我们能不能做出更好的模型"变成"我们能不能获得更多算力和数据"。规模成为第一优先级。

2. **算力军备竞赛开始**：如果性能主要由规模决定，那么拥有最多算力的公司就有最大的优势。Nvidia的股价开始飙升。

3. **可预测性**：你可以在小规模上验证，然后自信地投入大规模训练。降低了投资风险。

4. **Chinchilla的修正**：2022年DeepMind的Chinchilla研究表明，原始Scaling Laws可能低估了数据量的重要性——最优比例应该是参数和数据同步增长。这意味着很多大模型（包括GPT-3）其实是"过度参数化"的——用更少的参数和更多的数据可以达到同样或更好的效果。

## 稠密模型 vs 混合专家模型（MoE）

当参数量越来越大，一个问题浮现：**每次推理都要用全部参数，太贵了**。GPT-3的1750亿参数意味着每次生成都要计算1750亿参数的前向传播——延迟高、成本高。

### MoE的思路

混合专家模型（Mixture of Experts）的核心思想：**不是所有参数都参与每次计算——只激活最相关的"专家"**。

```
输入 → [路由器] → 选择Top-K个专家 → 只计算选中的专家 → 输出
```

每个MoE层包含多个"专家"（每个专家是一个标准的FFN），路由器决定每个token应该由哪些专家处理。典型配置是8-16个专家，每次激活2个。

### 代表模型

- **GShard（Google，2020）**：用MoE扩展Transformer到6000亿参数，用于多语言翻译
- **Switch Transformer（Google，2021）**：简化MoE路由（每次只选1个专家），1.6万亿参数
- **GLaM（Google，2022）**：1.2万亿参数，但推理时只激活约1/3的参数

MoE的优势是**推理效率**：1.6万亿参数的Switch Transformer在推理时只计算几百亿参数——因为每层只激活1/16的专家。

MoE的挑战：**负载均衡**——如果路由器总是选择同样的几个专家，其他专家就浪费了。需要额外的损失项鼓励均匀分配。

## Codex：AI学会编程（2021）

### 前因

自然语言的预训练已经很强，代码是另一种高度结构化的语言——有严格的语法、明确的逻辑、可验证的正确性。OpenAI的假设：在代码上做预训练，能否让模型学会编程？

### 原理

Codex是GPT-3在GitHub代码上的微调版本。训练数据来自数百万个公开GitHub仓库的代码。

关键评估：HumanEval——164个手工编写的编程题，每个题有函数签名、文档字符串、单元测试。模型需要生成通过所有测试的函数。

Codex在HumanEval上达到了28.8%的通过率（GPT-3只有0%）。经过改进的Codex达到了约70%。

### 后果

Codex直接催生了GitHub Copilot——一个AI编程助手，在IDE中实时建议代码补全。2021年发布后，Copilot迅速成为开发者最常用的AI工具之一。

Codex的意义不只是一个产品。它证明了**在特定领域（代码）的预训练可以赋予模型该领域的强大能力**——而且代码能力跟推理能力高度相关（第16章的推理模型也会在代码基准上展示最强能力）。

---

## 本章技术要点

1. **In-context Learning**：不修改参数，只在输入中给几个例子就能学会新任务。这是涌现能力的体现——小模型做不到，大模型突然会了。

2. **Scaling Laws**：Loss与参数量、数据量、算力呈幂律关系，可预测。核心结论：给定算力，参数和数据应同步增长。这改变了整个行业的投资逻辑。

3. **涌现能力的争议**：是真正的质变还是统计假象？不管答案如何，它为"继续scaling up"提供了实践合理性。

4. **MoE**：只激活部分专家，用更少的计算量支持更大的参数量。DeepSeek-V3后来用MoE把训练成本压到600万美元。

5. **Codex**：在代码上预训练赋予模型编程能力，催生GitHub Copilot。代码能力与推理能力高度相关。
