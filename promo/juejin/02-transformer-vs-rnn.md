# Transformer为什么能取代RNN？从注意力机制的诞生说起

> 本文改编自开源书籍《[AI简史：从感知机到大模型](https://github.com/matehubnet/AiHistory)》第9章和第11章。

---

2017年6月12日，八位Google研究员上传了一篇论文。标题像一个宣言：**Attention Is All You Need**。

注意力不需要依附在RNN上——它本身就是完整的架构。

此后发生的事大家都知道：GPT、BERT、T5、PaLM、Llama、Claude——每一个大语言模型都是Transformer的变体。RNN/LSTM几乎一夜之间从NLP的主力变成了历史遗迹。

但为什么？为什么自注意力这么有效？为什么RNN的"序列记忆"机制最终输了？

## RNN的根本困境：串行计算

RNN处理序列的方式是逐个元素、逐步更新隐藏状态：

```
h₁ = f(W·h₀ + W·x₁)
h₂ = f(W·h₁ + W·x₂)
h₃ = f(W·h₂ + W·x₃)
...
```

这就像读一本书，每读一个词就更新理解。直觉上很自然，但工程上有致命缺陷：**必须先算h₁才能算h₂，必须先算h₂才能算h₃**。

在GPU上有1000个核心也只能一个一个算。对于一个长度T的序列，需要T步串行计算。这就是LSTM训练慢的根本原因——不是参数多，而是无法并行。

更致命的是梯度消失。反向传播通过时间（BPTT）计算梯度时，沿时间步反向传递：

```
∂L/∂h₁ = ∂L/∂hₜ · Π(∂hₖ/∂hₖ₋₁)
```

20步后梯度几乎为零，100步后完全为零。RNN"忘记"了序列开头的信息——不是选择忘记，而是梯度无法回传那么远。

LSTM通过门控机制缓解了这个问题，但没有根治。长距离依赖仍然是LSTM的软肋。

## 注意力的诞生：从Seq2Seq的瓶颈开始

2014年，Bahdanau等人提出注意力机制，解决的是Seq2Seq的一个具体问题。

Seq2Seq的编码器把整个源序列压缩成一个固定长度的向量，解码器再从这个向量生成目标序列。问题是：**源序列越长，固定向量越难承载所有信息**。就像让你把一本小说总结成一句话，然后根据这句话写出另一种语言的翻译——信息损耗不可避免。

Bahdanau的解决方案：解码每个词时，不是看整个固定向量，而是**动态关注源序列的不同位置**。翻译"它"的时候，注意力集中在源句的"the animal"上；翻译"太累了"的时候，注意力集中在"too tired"上。

这是革命性的思路，但注意力此时还只是RNN的"辅助插件"。

## 自注意力：一步到位的信息传递

Transformer的核心创新是**自注意力（Self-Attention）**：同一个序列内部，每个位置直接关注所有其他位置。

```
句子："The animal didn't cross the street because it was too tired"

计算"it"的表示时：
- "it"与"animal"的注意力权重最高（0.6）
- "it"与"street"的注意力权重较低（0.2）
结果："it"的表示融合了"animal"的语义 → 理解"it"指代"animal"
```

信息传递路径的关键差异：

```
RNN:    位置1 → 2 → 3 → 4 → 5    (4步才能从1传到5)
自注意力: 位置1 ←→ 5              (1步直接传递)
```

在RNN中，100步的距离意味着梯度经过99次乘法，几乎必定消失。在自注意力中，1步和100步没有区别——每对位置之间都是直接的注意力。

而且所有位置的自注意力可以**完全并行计算**——因为位置之间没有依赖关系。这就是Transformer在GPU上训练速度远快于LSTM的根本原因。

## QKV：信息检索的直觉

Transformer用信息检索的框架描述注意力：

- **Query（Q）**：当前位置想找什么信息？"我是'it'，我在找一个名词来理解自己"
- **Key（K）**：每个位置能提供什么信息？"我是'animal'，我提供动物的信息"
- **Value（V）**：每个位置提供的具体内容

计算过程：

```python
Q = X * W_Q    # 投影到Query空间
K = X * W_K    # 投影到Key空间
V = X * W_V    # 投影到Value空间

Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) * V
```

1. QK^T → 计算每个Query和每个Key的点积，得到"兴趣程度"
2. / sqrt(d_k) → 缩放，防止softmax饱和
3. softmax → 归一化为概率分布
4. * V → 加权平均，得到融合了全局信息的表示

## 多头注意力：为什么需要多个头

一个注意力头学一种关联模式。但语言中的关联是多样的：

- 一个头关注语法关系（主语-谓语）
- 一个头关注指代关系（"it"-"animal"）
- 一个头关注语义关系（"tired"-"rest")

多头注意力让模型同时学习多种关联模式，然后把它们拼接起来。

## Transformer赢了，但不是完美的

Transformer解决了RNN的两个核心问题（串行计算和长距离依赖），但引入了新的代价：

- **O(n²)复杂度**：n个位置之间的注意力需要计算n²个得分。序列越长，计算量平方级增长。
- **缺乏顺序的天然感知**：RNN天然知道序列顺序（按时间步处理），但自注意力对所有位置一视同仁。Transformer用位置编码来"打补丁"——把位置信息加到输入里。

这些代价催生了后来的改进：Mamba/SSM尝试解决O(n²)问题，FlashAttention用IO感知优化让注意力跑得更快。

## 一个更深的洞察

Transformer的成功不仅是技术上的，更是哲学上的。RNN假设序列信息必须通过时间步逐步传递——这模拟了人类阅读的方式。但Transformer发现了一种不同的信息组织方式：**所有信息同时可见，每个位置自主选择关注什么**。

这不是"模拟人类阅读"，而是找到了一种更适合GPU计算的表示方式。计算效率上的优势反过来又使得模型可以更大、数据可以更多，而规模又带来了涌现能力——Transformer的成功是一个工程选择与科学发现的交叉点。
